Guía de Paso a Productivo

Implementación: Acta de Entrega y Acta de Devolución (QWeb) en Odoo.

Objetivo: dejar funcionando en productivo el reporte stock.report_deliveryslip con encabezado repetido por página, sin duplicidad de páginas y con el detalle de activos solicitado.

Fecha: 2026-05-08

1) Prerrequisitos técnicos del servidor

  • Servidor Odoo operativo.
  • Permisos de administrador en sistema operativo.
  • wkhtmltopdf instalado con patched qt.

Instalación recomendada (Ubuntu)

sudo apt update
sudo apt install -y xfonts-75dpi xfonts-base fontconfig libxrender1 libxext6 libx11-6
wget https://github.com/wkhtmltopdf/packaging/releases/download/0.12.6.1-2/wkhtmltox_0.12.6.1-2.jammy_amd64.deb
sudo dpkg -i wkhtmltox_0.12.6.1-2.jammy_amd64.deb || sudo apt -f install -y
sudo ln -sf /usr/local/bin/wkhtmltopdf /usr/bin/wkhtmltopdf
sudo ln -sf /usr/local/bin/wkhtmltoimage /usr/bin/wkhtmltoimage
wkhtmltopdf --version
Validación obligatoria: el comando debe retornar algo como wkhtmltopdf 0.12.6.1 (with patched qt).

Reiniciar Odoo después de instalar:

sudo systemctl restart odoo

2) Respaldo antes de cambios

  • Respaldar vistas QWeb actuales:
    • stock.report_deliveryslip
    • custom.layout_acta_entrega
    • custom.layout_acta_devolucion
  • Guardar evidencia del Formato de Papel actual (capturas o export).

3) Paso a paso: crear QWeb de layouts (desde cero)

  1. Activar modo desarrollador en Odoo.
  2. Ir a Ajustes > Técnico > Interfaz de usuario > Vistas.
  3. Crear la vista Layout Entrega:
    • Tipo de vista: QWeb.
    • Nombre sugerido: Layout Acta Entrega.
    • Key: custom.layout_acta_entrega.
    • Arquitectura: pegar XML final del layout de entrega.
  4. Crear la vista Layout Devolución:
    • Tipo de vista: QWeb.
    • Nombre sugerido: Layout Acta Devolución.
    • Key: custom.layout_acta_devolucion.
    • Arquitectura: pegar XML final del layout de devolución.
  5. Guardar ambas vistas.
  6. Editar la vista stock.report_deliveryslip y pegar la plantilla final validada.
  7. Guardar y actualizar el navegador (Ctrl+F5).

Punto crítico: KEY

Vista t-name Key (debe ser exacto)
Layout Entrega custom.layout_acta_entrega custom.layout_acta_entrega
Layout Devolución custom.layout_acta_devolucion custom.layout_acta_devolucion
Si el Key no coincide exactamente con el t-name, el reporte puede fallar con errores tipo KeyError por layout no encontrado.

4) Actualizar plantilla principal del reporte

  1. Abrir vista QWeb stock.report_deliveryslip.
  2. Pegar el contenido final validado del archivo de plantilla.
  3. Guardar cambios.

Nota técnica: la versión final evita duplicidad de páginas al no anidar un article adicional dentro del t-call al layout custom.

5) Paso a paso: crear Formato de Papel y parámetros

  1. Ir a Ajustes > Técnico > Reportes > Formatos de papel.
  2. Crear nuevo registro con nombre Supplies (o el nombre corporativo definido).
  3. Configurar los parámetros y guardar.
  4. Ir al reporte (stock.report_deliveryslip / Recibo de entrega) y asociar este formato de papel.

Parámetros recomendados

Campo Valor recomendado productivo Valor de pruebas (actual)
Nombre Supplies Supplies
Tamaño papel A4 (210 x 297 mm) A4 (210 x 297 mm)
Orientación Vertical Vertical
Margen superior (mm) 45 (rango sugerido 40-55) 200
Margen inferior (mm) 12 12
Margen izquierdo (mm) 7 7
Margen derecho (mm) 7 7
Mostrar línea de encabezado No marcado No marcado
Espaciado del encabezado 22 22
Deshabilitar encogimiento inteligente No marcado No marcado
DPI de salida 90 90
Importante: para productivo no dejar el margen superior en 200, porque genera espacio en blanco grande. Iniciar con 45 mm y ajustar en pasos de 5 mm (40, 45, 50) hasta que el encabezado quede alto, centrado y sin cortar contenido.

6) Pruebas funcionales obligatorias (UAT)

  • Entrega de 1 página.
  • Entrega de varias páginas.
  • Devolución de 1 página.
  • Devolución de varias páginas.

Validar en cada PDF

  • Encabezado repetido en todas las páginas.
  • Paginación correcta (Página X de Y).
  • Sin páginas duplicadas.
  • Sin bloques “sin encabezado”.
  • Sección “Detalle Activos” con usuario/licencias según datos disponibles.

7) Diagnóstico rápido de incidentes

Síntoma Causa probable Acción correctiva
6 páginas (mitad con header y mitad sin header) Estructura duplicada de article/page en QWeb Revisar plantilla final y dejar un solo flujo dentro de t-call.
No repite encabezado wkhtmltopdf sin patched qt o layout/key incorrectos Validar versión y corregir layouts + key.
Error KeyError de layout Key no coincide con t-name Corregir campo Key exactamente igual.
Espacio grande arriba Margen superior/header spacing alto Ajustar gradualmente en Formato de Papel.

8) Checklist de salida a productivo

  • [ ] wkhtmltopdf patched qt validado.
  • [ ] Odoo reiniciado.
  • [ ] custom.layout_acta_entrega actualizado y Key correcto.
  • [ ] custom.layout_acta_devolucion actualizado y Key correcto.
  • [ ] stock.report_deliveryslip actualizado.
  • [ ] Formato de papel validado.
  • [ ] Pruebas multipágina OK (entrega/devolución).
  • [ ] Aprobación funcional del proceso.

9) Rollback (contingencia)

  1. Restaurar XML anteriores de las 3 vistas QWeb respaldadas.
  2. Guardar y limpiar caché de assets si aplica.
  3. Reiniciar Odoo.
  4. Revalidar impresión estándar.
